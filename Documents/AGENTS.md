# AGENTS

## 架构红线

- 不允许合并 `Project` / `UserProject`
- 不允许删除 `SyncRun`
- 不允许破坏“GitHub 负责远端事实，本地数据库负责用户整理结果”的分层
- 不允许把远端状态变化改成自动硬删除本地记录

## API 约束

- API 路由保持 REST 风格
- 新接口优先延续当前 `routes + services` 分层
- 不要把核心同步逻辑搬到前端

## 数据库与 Prisma 约束

- Prisma migration 不允许 destructive reset
- 不允许为了省事使用会清空现有数据的重建方案
- 变更 schema 时优先考虑兼容已有 `Project / UserProject / SyncRun` 数据

## 前端约束

- 前端保持轻状态
- 不引入 Redux
- 不要为了当前规模过早引入重型状态管理框架
- 页面交互优先做“整理效率提升”，不是堆复杂状态抽象

## 分类系统约束

- AI 分类必须可选
- 规则分类始终是默认主路径
- 不允许让 AI 成为系统正常运行的前置依赖
- 手动整理结果必须优先于自动分类结果
- 优先做字段级保护，不要用粗暴的整条记录冻结

## 工程约束

- 保持自托管友好
- 部署与升级流程要能逐步补全文档，而不是绑定单一平台
- 修改现有同步、分类、删除逻辑时，优先保证数据安全和可恢复性
